# 注意

1. 每个Agent在自身任务执行完毕后，独立在项目目录 .front/AI_complete/ 新建本轮Agent任务总结文档，命名格式：xxx-agent-{agent名称}-task-summary.md，示例：001-agent-code-generator-task-summary.md。
2. 文档固定包含下面5部分：

- 接收上下文：简要总结该Agent接收到的上下文信息
- 本Agent任务目标：该Agent本次需要解决的子需求
- 执行过程：Agent推理思路、所有工具调用记录（如spawn调用Qodo、图片生成等）
- 文件变更清单：本Agent新增/修改/删除的文件，以及改动的核心逻辑
- 任务结果：是否完成、存在的报错、遗留问题、后续待办

1. 任务执行过程中，遇到关键节点、工具调用、接口报错、异常失败时，立刻写入简短快照保存到 .front/AI_logs/，命名格式 xxx-agent-{agent名称}-logs.md。
   普通内部推理思考过程不记录，减少冗余内容。一旦发生任务中断、手动强制退出，已经写入的快照文件保留，不会丢失追踪信息。
   - 不用每次微小动作都写；仅在工具调用、重大节点追加记录，普通思考推理过程不保存。
   - 禁止等到任务全部结束才一次性写入日志；关键事件触发就立刻落盘保存文件，保障任务强制退出时已有日志留存。
2. 文档使用markdown格式，内容简洁清晰。
3. 每个Agent只记录自己负责的子任务信息，不需要汇总其他Agent的执行内容；多个Agent并行执行时各自生成独立总结文件。

# Token节约强制规则（必须遵守）

1. 文件读取：仅读取当前任务必需的源码文件；禁止读取 node_modules、dist、日志全量内容、二进制文件。读取日志仅读取末尾最多300行。
2. 终端命令：相同命令禁止重复执行；命令失败最多重试1次，失败则停止。
3. 上下文控制：完成子任务后，丢弃完整终端原始输出，仅保留关键结果；不要持续加载无关文件、历史代码。
4. 输出要求：任务完成后，输出精简结论，禁止大段冗余描述，节约输出token。
